DDA Tool Dashboard Flood Landslide Earthquake Data Check Manual

Manual — running an assessment end to end

From a disaster report to a published DIBI / Jitupasna table and a GIS package, in the order you actually do it. Detection parameters and the science behind each hazard live on their own pages — Flood, Landslide, Earthquake. This page is the operating procedure that surrounds them.

0 · What the tool is, in one paragraph

A Google Earth Engine implementation of satellite-based post-disaster damage assessment for BNPB. It detects the footprint of a flood, landslide or earthquake from Sentinel-1/2 imagery, overlays that footprint on 38 curated exposure layers, and prices the damage in rupiah following the Jitupasna guideline (Perka BNPB No. 15/2011) and the reporting items of the DIBI database. Everything runs on Earth Engine; no local GIS software is needed to produce an estimate.

1 · Before you start

  • An Earth Engine account with access to the Cloud project that owns the Assets. Reading the published dashboard needs nothing; running the pipeline needs write access.
  • The scripts, in the Code Editor. Three folders, numbered in dependency order: 01_shared/ (the library everything else requires), 02_event/ (the per-event work — Stage 1 and Stage 2), 03_dashboard/ (Stage 3). See §2.
  • The Code Editor, not the published app. A published Earth Engine App cannot queue Export tasks. The dashboard's CSV downloads work in the app (they use a direct download URL), but every Asset export and every GIS export must be started from the Code Editor.
Two clocks to keep in mind. Anything computed on screen is killed by Earth Engine after about five minutes, on every billing plan. Anything computed as a batch export has no such limit. The whole tool is arranged around that split: the expensive work happens once, in batch, and every screen afterwards only reads the result. A province-wide valuation is a multi-hour batch task — start it and come back.

2 · The map of the tool

The folder numbers are the dependency order, which is why they read 01 → 02 → 03: the shared library comes first because everything else requires it, the per-event scripts come next, and the dashboard last because it only reads what they produced.

You only ever open four of these — the three detectors and the dashboard, plus Data Check when you want to inspect the inputs. Everything in 01_shared/01–06 is library code that the others require(); you edit it when a cost or a threshold changes, never to run an assessment.

3 · Stage 1 — detect the hazard

Open the script for the hazard you are assessing. The three detectors share the same panel layout and the same workflow; only the detection parameters differ, and those are documented on the hazard pages.

  1. Event ID. A short slug, e.g. jakarta_2025_nov. The script adds the hazard prefix and the export date for you, so what actually gets written is flood_jakarta_2025_nov_20260824. That full string is the event id and it is the key every later stage uses. The date stamp means re-running the same event on a later day never collides with the earlier result.
  2. Area of interest. Three ways: pick a province and a kabupaten/kota; pick a province and "(Whole province)"; or leave the province blank and draw a polygon on the map.
  3. Parameters. Dates, thresholds, sensor mode — see the hazard page.
  4. Preview. Renders the result on a coarser grid so it stays inside the interactive time limit. A province-wide preview is deliberately coarse and indicative; the export is the real thing. Use the preview to check that you have the right dates, the right area, and a plausible footprint — not to read areas off the screen.
  5. Export. Queues the Asset tasks. Nothing runs until you open the Tasks tab and press RUN on each one. This is the step people forget.

What each detector writes

HazardAssetsTasks
Flood floodmask_<id>, flooddepth_<id>2
Landslide landslidemask_<id>, roadblock_<id>2
Earthquake quakemask_<id>1

Only floods get a depth raster. For landslides and earthquakes the engine synthesises a constant saturating depth inside the extent, so every damage curve reaches 100 % — anything the hazard touched is treated as destroyed. That is the agreed treatment for both: a landslide removes what it crosses, and the earthquake verdict is binary collapsed / not collapsed by construction.

roadblock_<id> is a point per contiguous stretch where the slide crosses a national, regional or toll road — a possible road closure, marked × on the dashboard. It is a satellite-detected overlap, not a confirmed closure; ground confirmation remains the operator's job.

4 · Stage 2 — value the damage

Open 02_event/04_damage_calculation.js.

  1. Refresh the list and choose your event. An event only appears once its Stage-1 Assets have finished exporting — for a flood that means both the mask and the depth raster. If it is missing, your task is still running (or you never pressed RUN).
  2. Choosing it draws the extent and the district boundaries, so you can confirm you are about to value the right footprint.
  3. Press "Value everything and store the result". This queues two independent batch tasks. RUN both.
  4. Come back later. A single kabupaten finishes in minutes; a whole province can take hours. When the task is done, press "Refresh the list" and select the event again — the numbers appear.
AssetContents
damage_value_<id> The valuation. One row per district × damage class, plus facility counts, housing damage grades and population indicators. This is what the dashboard and both CSVs are built from.
affectedbld_<id> The whole building footprints the hazard touched. Feeds the dashboard's Housing overlay only. Queued separately so the numbers land first; the dashboard works without it, minus that one layer.

What the engine computes

For every damage class, at each 10 m pixel:

$$\text{damage}_{\text{IDR}} \;=\; \sum_{\text{pixels}} \Big[\, \text{quantity} \times \text{unit cost}_{100\%} \times \mathrm{DDF}(\text{depth}) \,\Big] \times \text{province ratio}$$
  • Quantity — exposed area (m² or ha) or length (km) in that pixel.
  • Unit cost — full reconstruction cost at 100 % damage, from Indonesian government price standards (DKI SHST 2025, HSPK, PUPR) and statistics. Every value is tagged with its source.
  • DDF — depth–damage function (JRC, Huizinga et al. 2017, Asia set). Evaluated per pixel, not on a district average, because the curves are non-linear.
  • Province ratio — regional construction-cost index (BPS IKK 2025, DKI Jakarta = 1.00). Not applied to the handful of classes whose unit cost is already a national average.

The same run produces the Sendai Framework indicators: affected facility counts (Target D), the damaged / destroyed housing split (C-4), and population (B-1, B-3, B-4). Every number can be traced to its inputs on the Data Check page.

If a province-wide export fails, the first switch to try is housingCount: false in the Stage-2 call. It drops only the estimated house counts and keeps every rupiah figure, facility count, population indicator and housing floor area.

5 · Stage 3 — read, export, publish

Open 03_dashboard/01_dashboard.js. It never computes a valuation; it reads the stored table, which is why it opens in seconds however large the event was.

5.1 Reading the dashboard

  • Event selector. Only events that still have both their valuation table and their hazard extent are listed. If a valuation is hidden, the Console says which and why — usually its Stage-1 mask was deleted.
  • KPI row — total damage, districts affected, people, houses, area, hardest-hit district.
  • Charts — damage by sector, top damage classes, top districts.
  • Map — hazard extent, per-district damage choropleth, flood depth (floods only), exposure overlays, and the × road-closure markers where a roadblock_ Asset exists.
  • Click any district to re-scope the class-totals table to it. "← All cities" returns to the event-wide view.

5.2 The two CSVs

ButtonFormat
Export DIBI CSV The per-year Data Bencana schema — 98 Indonesian-named columns in the published order, one row per district. Columns the tool measures start at numeric 0; everything satellite cannot observe (casualties, chronology, demographic breakdowns) is left blank, the same convention the published file uses. Money is summed into kerugian_juta (millions of rupiah). Tool-specific additions are appended after the official 98 with an x_ prefix.
Export Jitupasna CSV Long format: one row per district × damage class, with quantity, unit cost, effective damage ratio and rupiah. This is the file to use when you need to see how a number was reached.

Both appear as a green download link in the header when ready. They are direct downloads, not Tasks, so they also work from the published app.

5.3 GIS download — the exposed features

The right column has Export exposed features (GIS). One press queues a Drive-export task for every exposure layer, each filtered to the features that actually intersect the loaded event's hazard extent.

  1. Load an event.
  2. Choose a format — GeoJSON (default), SHP, CSV or KML. GeoJSON is the safe default: shapefiles are capped at 2 GB and 255 columns, which the housing layer can exceed.
  3. Press Queue Drive exports (all layers).
  4. Open the Tasks tab and RUN them. Files arrive in Google Drive under DDA_<event id>.

Exported polygons are the whole footprints of the affected features, never clipped to the hazard extent — a half-flooded hospital is exported as a whole hospital, with an exposed column marking it. The housing layer is read from affectedbld_<id> when Stage 2 has produced it. Batch exports have no size limit, but this is Code Editor only.

5.4 Publishing the Assets — the sharing button

Why this step exists. A published Earth Engine App reads Assets as whoever opens it, not as whoever published it. Until the Assets are public, the app works only for you. And it cannot be folded into the export: Export.*.toAsset has no sharing parameter, and could not use one, because the Asset does not exist until the task finishes. Publishing is always a second pass.

The right column has Share BNPB Assets (visible only to the owner of the Assets — the app hides it from visitors, who could not use it anyway).

  1. Press once. It walks the whole BNPB tree and reports how many Assets are still private, listing them in the Console. Nothing has changed yet.
  2. Read the list.
  3. Press again to publish them. Each write is read back from the server before it is counted, so the reported figure is what is actually true of the Assets, not what the call attempted.

Run it after every round of exports. Already-public Assets are never rewritten, and the owner plus any individual reader you granted are carried through untouched. Folders are published too — a private folder cannot be listed by anyone else, so publishing its contents while leaving the directory shut would be half a job.

Licences travel with the data. The OSM-derived exposure layers (worship, markets, offices, shops, hotels, fuel, factories, clinics) are ODbL: publishing them obliges you to attribute OpenStreetMap and keep derivatives open. The flood-depth rasters derive from FABDEM, CC BY-NC-SA 4.0 — attribution, share-alike, and non-commercial. Publishing is compatible with that licence; commercial use is not. Say so wherever you link the data.

6 · Data Check — verifying the inputs

01_shared/07_datacheck.js renders every input the valuation depends on, before you trust a number built on it. It does no server-side computation, so it opens instantly.

  • Unit Costs — every value with its source reference.
  • DDF Curves — each curve plotted, plus a depth-vs-ratio table.
  • Province Ratio — the BPS IKK 2025 multipliers.
  • Crops & Fish — per-m² production values.
  • Exposure — every layer with its producing ministry, feature count and the DIBI column it feeds. At the bottom, Verify every Asset probes all 38 exposure layers plus the boundaries and land cover, and reports each as present or NOT FOUND. Run this after any Asset is added, renamed or moved — a missing source Asset does not degrade quietly, it stops the whole valuation.
  • Sanity Test — a worked example: one house at 1.5 m of water, priced by hand, then repeated across provinces.
  • Engine Test — checks the per-pixel damage curve against the reference implementation on every curve, and guards the population arithmetic against the resolution trap that would inflate it 100-fold.

7 · Where the Assets live

BNPB/
├── admin/      administrative boundaries (BPS 2020, adm1/2/3)
├── events/     per-event outputs — ALL hazards
├── exposure/   the 38-layer exposure catalog
├── logo/       BNPB and JICA marks for the dashboard header
└── lulc/       in-house Random-Forest land cover (2025, 30 m)

events/ was called flood/ until floods stopped being the only hazard. Retired data (the superseded DEMNAS 8 m mosaics) and debug leftovers live outside BNPB, because dead weight inside the live tree reads as live.

Naming is positional and every stage relies on it: <prefix>_<event id>, where the prefix is one of floodmask_, flooddepth_, landslidemask_, quakemask_, roadblock_, damage_value_, affectedbld_. The event id itself starts with flood_, landslide_ or quake_, and that prefix is what tells the engine which hazard it is looking at.

8 · The routine, start to finish

  1. Stage 1 — set the event id, area and dates; Preview; Export; RUN the tasks.
  2. Wait for them to finish.
  3. Stage 2 — Refresh, choose the event, Value everything; RUN both tasks.
  4. Wait. A province takes hours.
  5. Dashboard — Refresh, choose the event, check the figures look plausible.
  6. Dashboard — Share BNPB Assets, twice, so the new Assets are readable by the app.
  7. Dashboard — Export DIBI CSV and Jitupasna CSV.
  8. Dashboard — Queue the GIS exports if you need the shapefiles; RUN them.
  9. Data Check — Verify every Asset if anything was added or moved.

9 · When something goes wrong

What you seeWhat it means
Collection asset not found A source Asset the catalog names has not been ingested, or was renamed. Run Verify every Asset on the Data Check page — it names the missing one.
The event is missing from a dropdown Its Stage-1 export has not finished, or you never pressed RUN. In the dashboard it can also mean the hazard extent was deleted — the Console lists any event hidden for that reason.
Computation timed out on screen Something interactive is trying to do batch-sized work. Narrow the area, or let the batch export do it.
A province-wide export dies Try housingCount: false — it keeps every monetary figure and drops only the estimated house counts.
The app works for you but not for others The Assets are still private. Press Share BNPB Assets. Note that newly created folders are private even when their contents are public.
Export is undefined You are in the published app. Asset and Drive exports must be started from the Code Editor.
The sharing checkbox looks wrong in the Assets tab That tab caches sharing state. Reload the Code Editor; the figure the button reports was read back from the server.
